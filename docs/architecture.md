# Architecture

Toolstile serves independent users through one gateway endpoint. Each person's connections, encrypted credentials, agents, devices, grants and activity remain isolated. The application uses TanStack Start, oRPC, Better Auth, Drizzle and the official MCP SDK.

The default Node 24 runtime uses one PostgreSQL schema: embedded PGlite on local disk for local installations, or a PostgreSQL server for server/container deployments. A transaction binds one checked-out connection; pool queries made inside it join it, and opening a second transaction or connection on the same database from inside it fails. Transactions run at read committed: each invariant is a single atomic statement (a conditional update, `INSERT ... ON CONFLICT`) or rests on a row lock taken before the reads it protects, with an advisory transaction lock only for a key that has no row yet. Primary reads enforce current revocation/policy; cached membership or replica state cannot extend access. Current migrations are `apps/web/postgres-migrations`.

Node MCP sessions and live transports are process-local. Eviction/restart returns a reinitialization boundary instead of fabricating SDK state or blindly replaying a tool action. Replay buffers and continuation state have explicit limits; do not infer horizontal session forwarding or HA. Rotating-token refresh marks uncertainty durably before network effects and fences stale completions. Persistent maintenance runs while the process is alive; authorization never waits for cleanup.

Agents see each connection's tools and prompts as `<namespace>__<upstream name>`, such as `linear__get_issue`, with upstream descriptions and schemas unchanged. A name that would exceed MCP's 128-character limit keeps the fixed-length opaque name described below. The namespace comes from the connection's label when it is first listed; later connections with the same base get `linear2`, `linear3` and so on. Namespaces are stored in `source_namespaces` and never reassigned, even after their connection is deleted or renamed, so a name an agent saw cannot reach a different account. Blocks, grants and approvals use the upstream name. The older opaque `c<id>_<hash>` names are still accepted for their own connection.

The Node transport supports explicitly configured private services, excludes reserved/metadata addresses, pins connection DNS and refuses redirects. MCP ingress bounds the actual body at 2 MiB with a ten-second read deadline before SDK routing/parsing, regardless of declared Content-Length.

The catalog has a bundled fallback; local and customer-owned deployment do not depend on toolstile.com. See [local storage](local-operation.md), [server packaging](installation.md), [approvals](approvals.md) and [tool review](tool-review.md). The application runs as one Node process on PostgreSQL or embedded PGlite, initialized from `apps/web/postgres-migrations`.
