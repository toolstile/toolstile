# Local environment policy

The [development guide](development.md) owns lifecycle commands and recovery. [Verification](verification.md) owns the disposable test fixture. Neither lifecycle preparation nor tests copy a main-checkout dotenv or inherit provider credentials from the shell.

## Runtime ownership helper

`scripts/worktree-resources.mjs` exports `runLifecycle(config, command, { cwd = process.cwd(), allowMain = false, run })` and `runLifecycleCli(config)`. Importing it performs no I/O. `run` is a test seam replacing the default `vp` executor; production adapters normally use the default. CLI commands and the explicit main flag are documented once in the development guide. API results are records or `{name, phase, origin}`; CLI output includes only those non-secret summary fields.

Configuration requires `envPath` (checkout-relative dotenv), `appDir` (checkout-relative Vite directory) and `portStart`, the base of the stable per-checkout port used for the generated `http://localhost:<port>` origin. `originFallback(env)` optionally returns the origin `dev` serves when the invoking environment has no `BETTER_AUTH_URL`; otherwise it serves `http://localhost:$PORT`. The helper always generates fresh independent auth/encryption keys for a new generation. `environment` supplies explicitly allowlisted adapter settings through `environmentPolicy: {allowKeys, defaults}`; task database, auth origin and keys remain owned by the helper. No adapter may use production credentials or make remote provider changes during setup.

Callbacks receive `ctx` and the version-2 `record`. `ctx` contains `config`, canonical `dir`, `main`, `common`, `gitDir`, stable `name`, manifest `file`, runtime `directory` and `envPath`. Records bind those paths and their identities, the generation `id`, `server: {kind: 'sqlite', directory, progress, identity?}` (a historical label kept for existing records; storage is a PGlite directory), environment metadata, progress and owned processes. Adapters can add fields for positively owned local dependencies without weakening the core checks. `server.progress` advances from `pending` (reservation only, no directory ownership) through `directory-created` (canonical device/inode recorded) to `ready` (generation marker verified). `beforeSetup` runs only after `ready`. Teardown callbacks can receive an incomplete initialization; their signatures and ordering are unchanged. An absent pending reservation can resume or discard its metadata; any path substituted at that reservation is retained. A recorded empty initial directory can retry marker creation or be removed after validation. A directory created before its identity could be persisted remains unproven and requires manual inspection.

- `beforeSetup(ctx, record, save)` runs before installation on each setup/resume. Provision task-owned dependencies idempotently; call `save()` after recording ownership/progress. It must tolerate partial prior work.
- `install(ctx, record)` replaces the default frozen `vp install` when an adapter has dependency preparation of its own. It runs after `beforeSetup`; the helper still generates the environment and runs `db:migrate`.
- `checkReady(ctx, record)` runs after migrations and core readiness checks, and during read-only `check`/audit. It must inspect without modifying resources. Running-server setup/resume only validates readiness and does not reinstall/migrate.
- `beforeTeardown(ctx, record)` validates adapter resources before any process stop or runtime deletion. An error retains runtime resources.
- `afterTeardown(ctx, record)` removes only positively owned adapter resources after core runtime deletion and before manifest deletion. It must tolerate retries with missing resources. Source worktree removal and integration belong to the worktree provider.

`auditResources(config, cwd = process.cwd(), adapters = {})` returns `{issues: string[], notes: string[]}` without creating, adopting, stopping, deleting or repairing anything. It inspects manifests in that checkout's Git common directory; `adapters.processes` optionally supplies process inspection in tests. Missing owner checkouts, malformed records and changed ownership are issues. Legacy/unknown versions and unrecorded directories are reported as retained. An unavailable inspection is reported rather than considered clean. Callers decide exit status and present both fields.

## Pure environment helpers

`scripts/local-environment.mjs` performs no I/O or environment mutation on import. `runtimeEnvironment(source)` carries only process essentials. `isolatedWorktreeEnvironment(source, {name, database, origin, allowKeys, defaults})` copies core development values and explicitly allowed settings, drops TEST variables, and accepts an absolute task-owned PGlite directory or a validated local PostgreSQL URL. `serializeEnvironment` emits dotenv assignments and rejects unsupported quotes/newlines.

`localTestEnvironment(file, inherited, options)` validates explicitly selected disposable PostgreSQL targets, refusing conflicting file/shell targets, remote databases and redirecting query parameters. `databaseNames`/`databaseHosts` and `originTargets` define exact allowed fixture targets. The current full test harness allocates its own disposable PostgreSQL; focused storage fixtures may use PGlite. Legacy version-1 ownership helpers (`assertTestOwnership`, `assertIdentity`, `databaseMatches`) do not authorize adopting or deleting old storage. Version-2 teardown removes only positively owned current resources.
